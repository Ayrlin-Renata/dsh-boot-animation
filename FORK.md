# FORK.md — maintaining the English fork

Upstream: `NativeDog1/dsh-boot-animation`. This fork: `Ayrlin-Renata/dsh-boot-animation`.

Upstream writes code, comments and identifiers in **English** and ships the
user-facing strings in **Chinese**. This fork ships an **English UI** while
keeping `src/` byte-identical to upstream, so `git merge upstream/main` never
produces a hand-resolved conflict in `ui.ts` — the 623-line file upstream edits
most.

## The one rule

**Never edit anything under `src/`.**

That is the entire reason this fork is cheap to update. `src/client/ui.ts` is
Chinese today and upstream will keep editing it; the moment you translate in
place, that file forks permanently and every merge is yours to resolve.

## How it works

```
src/client/**.ts   ──( i18n/en.json )──▶   build/i18n/client/**.ts   ──▶   tsdown   ──▶   lib/client.js
   read-only, byte-identical to upstream        generated, never committed        shipped, English
```

`scripts/i18n.mjs` reads `src/client`, swaps each Chinese string literal for its
English translation from `i18n/en.json`, and writes the result into
`build/i18n/client`. `tsdown.config.ts` — the only upstream build file this fork
touches — compiles **that** instead of `src/`.

It uses the TypeScript parser (already a devDependency) rather than a regex,
because the unit of translation is a whole string literal: UI text here is
stitched together, e.g. `ui.ts:360` builds `'这一段在磁盘上有 ' + copies + ' 份相同的副本…'`.
Matching Chinese *runs* would translate half a sentence.

### The build fails closed

A staging step that silently skips an unknown string is worse than no
localization at all — the build would pass and ship Chinese. So `npm run build`
**aborts** if:

- a source literal has no entry in `i18n/en.json`,
- a translation still contains CJK, or
- any CJK survives into the staged output.

A silent mixed-language build is the one unacceptable outcome here.

## Commands

Run these directly — this fork deliberately adds no npm scripts, because
`package.json`'s `scripts` block is the highest-frequency upstream conflict site.

| Command | What it does |
| --- | --- |
| `node scripts/i18n.mjs report` | Lists untranslated literals (`file:line` + exact literal) and stale entries. Exits 0. |
| `node scripts/i18n.mjs stage` | Regenerates `build/i18n/client`. Already runs inside `npm run build`. |
| `node scripts/i18n.mjs check` | Stages, then asserts `lib/client.js` is CJK-free. Run after a build. |
| `npm run build` | Full build. Fails closed on untranslated strings. |
| `npm run check` | Upstream's 15 verification groups. |

> **Do not `rm -rf lib` when cleaning.** `lib/types/index.d.ts` and
> `lib/types/client/index.d.ts` are committed but generated by **nothing** —
> they are hand-written stubs, and `tsdown.config.ts` sets `dts: false` while
> `scripts/build.mjs` only ever prunes inside `lib/host/`
> (`scripts/build.mjs:53-60`). A clean rebuild reproduces every other artefact,
> but those two stubs are lost for good. Recover with
> `git checkout -- lib/types/`.

## Updating from upstream

```bash
git fetch upstream
git merge upstream/main
npm install
npm run build
```

If upstream added or changed a Chinese string, `npm run build` stops and prints
every literal that needs a translation, with its `file:line`, plus a
ready-to-paste JSON block. Paste it into `i18n/en.json` under `"strings"`, fill
in the English, and build again:

```bash
node scripts/i18n.mjs report    # confirm: 0 untranslated
npm run build
node scripts/i18n.mjs check     # confirm the bundle is English
npm run check                   # upstream's suite
```

That is the whole cost of an upstream update: **translate whatever is new.**
No code review of a 623-line UI diff.

### Two expected failures after a merge

- **`npm run build` stops on new strings.** That is the fail-closed gate, not a
  breakage. Follow the steps above.
- **`verify:build` fails on a stale bundle.** `scripts/verify-build.mjs` asserts
  `lib/client.js` is newer than the newest file under `src/client`. A fresh
  merge gives `src/` newer mtimes, so it fails until you rebuild. Run
  `npm run build`.

## Changing a string

`i18n/en.json` is the single source of truth for UI text, keyed by the **exact
source literal**, including its leading/trailing spaces:

```json
"strings": {
  "刷新": "Refresh",
  " · 预览中": " · Previewing"
}
```

Keys are the Chinese text itself. That makes upstream's diff the dictionary: a
changed upstream string simply stops matching and shows up as untranslated, which
is exactly the signal you want.

`report` also lists **stale** keys (upstream no longer uses them). They are
inert but safe to delete.

### Style used in this file

Consistent on purpose, so future translations match:

- "intro" for 片头, "intro library" for 片头片库.
- Button labels stay short: `Refresh`, `Close`, `Skip`, `Choose`, `Preview`.
- Non-ASCII typography is **kept**, not stripped: `▶ ⚠ ✓ 🎲`, the em dash, the
  ellipsis, the middle dot, curly quotes. Upstream's UI already uses it. Only
  CJK is considered a bug — see `isChinese()` in `scripts/i18n.mjs`, the single
  definition of that rule.

## What this fork owns

| Path | Status |
| --- | --- |
| `src/**` | **Untouched.** Byte-identical to upstream, forever. |
| `scripts/verify-*.mjs`, `scripts/*.mjs` | **Untouched.** |
| `i18n/en.json`, `scripts/i18n.mjs`, `FORK.md` | Fork-owned. Upstream has no opinion; zero conflict surface. |
| `tsdown.config.ts` | The only upstream build file touched — 2 added lines, 1 changed. |
| `.gitignore` | Appended `/build/`. |
| `lib/client.js`, `lib/client.js.map` | Committed build output; regenerated by `npm run build`. |
| `build/` | Generated, gitignored. |

### Deliberately out of scope

- **Built-in clip display names stay Chinese** (`cyberpunk`, `awakening`,
  `startup` in `scripts/embed-clips.mjs`). They are media metadata, not UI copy,
  and translating them would break
  `scripts/verify-conversation-override.mjs:65`, which asserts the host
  acknowledges a clip by name. Plugin **UI strings only** is the scope.
- **`src/host/**` is already English** — no CJK there at all, so nothing to do.
- **`README.md` / `CHANGELOG.md` stay untouched** to keep merge conflicts low.
- **`package-lock.json` is left as upstream ships it.** Upstream renamed the
  package without regenerating the lock; `npm install` will dirty it. Revert it
  rather than commit it, unless you mean to fix the lock upstream.

## Why this is the maintainable shape

The alternative — translating `ui.ts` in place — produces a permanently diverged
file in the one place upstream changes most. The cost is not the initial diff,
it is every future merge, forever, and it gets worse with every release.

Here, the tracked source is upstream's, so `git merge` is textually clean. All
the fork's intelligence lives in `i18n/en.json`, which upstream never touches.

Verified: after a full build, `lib/client.js` is **token-identical** to the
upstream bundle once string contents are ignored — same 5260-node AST. The fork
changes UI text and nothing else.
